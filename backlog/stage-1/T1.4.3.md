# Config validation test matrix

## Objective
Write a parameterized test matrix covering missing required vars, invalid types,
out-of-range values, defaults, and env-prefix handling for `CoreConfig`.

### Not Included
- The config model (T1.4.1) and startup wiring (T1.4.2)
- Secrets/vault validation
- Integration with deployment manifests

## Context
DoD criterion C0.6 requires validated configuration. This matrix is the evidence
artifact and runs in the Stage 1 merge gate (T1.5.1).

## Tech Stack & Constraints
- Python 3.11
- `pytest` + `pytest.mark.parametrize` + `monkeypatch` for env vars
- Each case isolated: no env leakage between cases

## Input/Output Contracts

```python
CASES = [
    ("valid", {...}, None),
    ("missing_state_dir", {...}, "PIPELINE_STATE_DIR"),
    ("bad_type", {...}, "int_parsing"),
    ("out_of_range", {...}, "less_than_equal"),
]
```

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | Valid env | Config validates | `pytest -k valid` |
| AC2 | Missing required var | Error names the env var | `pytest -k missing` |
| AC3 | Wrong type | Type error reported | `pytest -k type` |
| AC4 | Out-of-range value | Bound error reported | `pytest -k range` |
| AC5 | Optional fields absent | Documented defaults applied | `pytest -k defaults` |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Isolate env per case; assert on the specific failing field |
| Ask First | Adding cases for experimental settings |
| Never | Depend on the developer's real environment; assert on message text verbatim |

## Test Plan
- Unit: `pytest tests/test_config_matrix.py -v`
- Type: `mypy --strict tests/test_config_matrix.py`
- Self-verify: Run all 5 ACs. Cite test names and pass/fail.
