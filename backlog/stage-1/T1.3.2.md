# Implement the append-only event stream

## Objective
Implement an append-only event stream with an in-memory backend for the MVP and a
file-backed backend for production. Entries are never modified or removed once
appended.

### Not Included
- Replay for recovery (T1.3.4)
- Secret redaction of payloads (T5.2.3)
- External log shipping
- Multi-process / multi-agent write concurrency (Stage 5, C4.5)

## Context
DoD criterion C0.5 requires an append-only, immutable stream with zero violations
across 10K events. The stream backs the audit requirement C2.9.

**Concurrency scope note:** this task makes a **single-process** backend safe
(internal lock around `append`). Cross-process / multi-agent safety (two agents
writing the same file) is a separate Stage 5 concern (T5.4.2) and is NOT in scope
here. The immutability property test (T1.3.3) therefore runs **single-threaded**.

## Tech Stack & Constraints
- Python 3.11
- `Event` from T1.3.1
- Backends share one interface; swap via configuration
- A lock guards the in-memory sequence counter and list

## Input/Output Contracts

```python
class EventStream(Protocol):
    def append(self, event: Event) -> Event: ...   # assigns sequence_number
    def read_all(self) -> list[Event]: ...
    def __len__(self) -> int: ...
```

- `append` assigns the next monotonic `sequence_number` (atomic within a process)
- `read_all` returns a copy; callers cannot mutate internal state

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | Append N events | Sequence numbers are 0..N-1, monotonic | `pytest -k append_monotonic` |
| AC2 | `read_all` then mutate result | Internal stream unchanged | `pytest -k read_copy` |
| AC3 | No API for delete/update | Stream exposes no mutation method | `pytest -k no_mutation_api` |
| AC4 | Restart with file backend | Prior events reloaded intact | `pytest -k file_backend_persist` |
| AC5 | Concurrent `append` in one process | No duplicate/lost sequence numbers | `pytest -k append_locked` |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Assign sequence numbers inside `append`; return defensive copies; lock mutations |
| Ask First | Adding a backend; changing the on-disk record format |
| Never | Expose update/delete; mutate an event after it is appended; claim multi-process safety here |
