# Implement the state schema migration framework

## Objective
Implement a migration framework that converts persisted state from version N to
version N+1 through a registry of typed migration converters, applied in sequence
until the state reaches the current version.

### Not Included
- Specific migration pairs beyond the v1 → v2 example converter
- Serialization/checksums (T1.2.4)
- Backward (downgrade) migrations

## Context
DoD criterion C0.4 requires 100% backward compatibility for stored state. A
converter registry keeps migrations explicit, ordered, and testable instead of
embedding version logic inside each model (ADR-004).

Migrations operate on **typed Pydantic models** (not raw dicts) so that
"no field loss" is assertable by field name and type-checked by `mypy --strict`.

## Tech Stack & Constraints
- Python 3.11, Pydantic v2.x, `BaseState` from T1.2.1
- One model class per version (`StateV1`, `StateV2`, …), all deriving from `BaseState`
- Migrations are pure functions between typed models

## Input/Output Contracts

```python
Migration = Callable[[BaseModel], BaseModel]  # StateV{n} -> StateV{n+1}

class MigrationRegistry:
    def add(self, from_version: int, to_version: int, fn: Migration) -> None: ...
    def migrate(self, state: BaseState, target: int) -> BaseState: ...
```

- Consecutive migrations only (`to_version == from_version + 1`)
- Missing path from N to target raises `MigrationError` naming the gap
- Input model is parsed, never mutated; output is a fresh instance

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | `StateV1`, target v2 | Valid `StateV2` returned | `pytest -k migrate_one_step` |
| AC2 | `StateV1`, target v3 with v1→v2, v2→v3 | Both applied in order | `pytest -k migrate_chain` |
| AC3 | Gap in the chain | `MigrationError` names the missing step | `pytest -k migrate_gap` |
| AC4 | Target equals current | Input returned unchanged (by value) | `pytest -k migrate_noop` |
| AC5 | Non-consecutive registration | Rejected at `add` time | `pytest -k migrate_validate` |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Keep migrations pure and typed; fail loudly on gaps |
| Ask First | Adding a skipped-version migration; changing the target-version rule |
| Never | Mutate the input model in place; apply migrations out of order; silently drop unknown fields |
