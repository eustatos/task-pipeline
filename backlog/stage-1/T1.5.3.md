# Add a schema generation test for all tools

## Objective
Add a test that generates the JSON Schema for every registered tool's input and
output models and asserts each schema is valid, so contract drift fails the build.

### Not Included
- The `ToolSpec` model (T1.1.1)
- The registry implementation (T1.1.2)
- IDE binding of the exported schemas

## Context
DoD criterion C0.1 requires typed, validatable tools. Verifying that every tool
produces a valid JSON Schema enforces the contract at the schema level, not only
at runtime validation.

## Tech Stack & Constraints
- Python 3.11
- Pydantic v2.x `model_json_schema()`
- Validator: `jsonschema` (Draft 2020-12)

## Input/Output Contracts

```python
def test_all_tool_schemas_valid() -> None:
    for spec in registry.all_specs():
        jsonschema.Draft202012Validator.check_schema(
            spec.input_schema.model_json_schema()
        )
        jsonschema.Draft202012Validator.check_schema(
            spec.output_schema.model_json_schema()
        )
```

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | Registered tool set | Every input schema validates | `pytest -k input_schemas` |
| AC2 | Registered tool set | Every output schema validates | `pytest -k output_schemas` |
| AC3 | Malformed schema fixture | Test fails with the tool name | `pytest -k malformed_schema` |
| AC4 | Empty registry | Test passes with a clear no-op message | `pytest -k empty_registry` |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Validate against Draft 2020-12; report the offending tool name |
| Ask First | Changing the JSON Schema draft version |
| Never | Skip tools silently; catch schema errors and pass |
