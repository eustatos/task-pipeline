# Role-based filtering integration test

## Objective
Write an integration test that registers a realistic tool set and asserts exact
role isolation for Planner, Executor and Reviewer, proving zero cross-role
tool leaks.

### Not Included
- Unit tests for individual registry methods (T1.1.2/T1.1.3)
- Graph-level routing tests (Stage 2)
- Concrete tool implementations (Stage 3)

## Context
DoD criterion C0.3 requires 0 cross-role tool leaks. This integration test is the
evidence artifact and runs as part of the Stage 1 merge gate (T1.5.1).

## Tech Stack & Constraints
- Python 3.11
- `pytest`
- Builds on `ToolRegistry` (T1.1.2) and role access (T1.1.3)

## Input/Output Contracts

```python
EXPECTED = {
    AgentRole.PLANNER:  {"get_repo_map", "analyze", "plan"},
    AgentRole.EXECUTOR: {"apply_diff", "run_tests", "checkpoint", "read_file"},
    AgentRole.REVIEWER: {"read_file", "run_tests", "get_repo_map"},
}
```

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | `list_for_role` per role | Exact set equals `EXPECTED[role]` | `pytest -k exact_sets` |
| AC2 | Cross-role `get` calls | `AccessDeniedError` in every case | `pytest -k no_leaks` |
| AC3 | Full matrix Planner/Executor/Reviewer × tools | Zero leaks | `pytest -k matrix` |
| AC4 | Unknown tool for a valid role | `RegistryError` (not `AccessDeniedError`) | `pytest -k unknown_tool` |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Assert on exact sets, not supersets; cover every role |
| Ask First | Changing the expected tool-to-role mapping |
| Never | Weaken assertions to make the test green; assert only on counts |
