# Define the Event Pydantic model with typed payloads

## Objective
Define the `Event` Pydantic model describing a single entry in the append-only
event stream: type, typed payload, timestamp, and sequence number.

### Not Included
- The event stream implementation (T1.3.2)
- Replay logic (T1.3.4)
- Prometheus export of stream metrics (T4.3.3)

## Context
The event stream is the immutable audit log referenced by DoD criteria C0.5 and
C2.9. `Event` is the shared record format for every tool call and state change
(F11 in the feature map).

Payloads are **typed per event type** (a discriminated union keyed by `type`),
not raw dicts, so replay reducers (T1.3.4) are type-safe and audit records are
self-describing.

## Tech Stack & Constraints
- Python 3.11, Pydantic v2.x (see `backlog/_conventions.md`)
- `timestamp` is timezone-aware UTC
- `sequence_number` is a non-negative monotonic integer

## Input/Output Contracts

```python
class EventType(str, Enum):
    TOOL_CALL = "tool_call"
    STATE_CHANGE = "state_change"
    CHECKPOINT = "checkpoint"

class ToolCallPayload(BaseModel):
    tool: str
    input_hash: str
    output_hash: str
    duration_ms: float

class StateChangePayload(BaseModel):
    from_version: int
    to_version: int

class CheckpointPayload(BaseModel):
    task_id: str
    git_sha: str

PAYLOADS: ClassVar[dict[EventType, type[BaseModel]]] = {
    EventType.TOOL_CALL: ToolCallPayload,
    EventType.STATE_CHANGE: StateChangePayload,
    EventType.CHECKPOINT: CheckpointPayload,
}

class Event(BaseModel):
    sequence_number: int        # >= 0, monotonic
    type: EventType
    payload: BaseModel          # validated as PAYLOADS[type] at construction
    timestamp: datetime         # tz-aware UTC
```

> `payload` is validated against `PAYLOADS[type]` via a field validator so a
> `ToolCallPayload` is required for `type=tool_call`, etc.

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | Valid event + matching payload | Instantiates | `pytest -k event_valid` |
| AC2 | `type=tool_call` with wrong payload type | ValidationError raised | `pytest -k payload_mismatch` |
| AC3 | `sequence_number=-1` | ValidationError raised | `pytest -k sequence_non_negative` |
| AC4 | Naive `timestamp` (no tz) | ValidationError raised | `pytest -k tz_aware` |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Require tz-aware timestamps; validate payload against its event type |
| Ask First | Adding new `EventType` members; changing a payload shape |
| Never | Store a payload type that does not match `type`; allow negative sequence numbers |
