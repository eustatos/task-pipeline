# Define CoreConfig with 3-level source merging

## Objective
Define `CoreConfig` as a Pydantic Settings model that reads from a 3-level
source hierarchy: CLI flags > project file (`.backlog.yml`) > user file
(`~/.config/backlog/config.yml`) > built-in defaults. Secrets (API keys,
tokens) are sourced **only** from environment variables and are never written
to config files.

### Not Included
- Fail-fast startup wiring (T1.4.2)
- The validation test matrix (T1.4.3)
- The `--dry-run` / `--parallel` CLI flag parsing (that is the CLI layer, not
  CoreConfig)
- Secrets management integration

## Context
ADR-010 mandates a 3-level configuration model:
CLI flags > Project config > User config > Defaults.
DoD criterion C0.6 requires validated configuration at startup (ADR-005).

The split is:
- **Non-secret settings** (model name, log level, sandbox mode, parallelism):
  can be set in `.backlog.yml`, `~/.config/backlog/config.yml`, or overridden
  via CLI flags.
- **Secrets** (API keys, auth tokens): **environment variables only**, always
  prefixed `BACKLOG_`. Never written to files. This keeps `.backlog.yml` safe
  to commit.

## Tech Stack & Constraints
- Python 3.11, `pydantic-settings` v2.x (see `backlog/_conventions.md`)
- Project file: `.backlog.yml` at the project root
- User file: `~/.config/backlog/config.yml`, path overridable via `BACKLOG_CONFIG`
- Secrets: `BACKLOG_API_KEY`, `BACKLOG_MODEL_API_KEY`, etc. (env only)
- No secret value may appear in a config file

## Input/Output Contracts

```python
class CoreConfig(BaseSettings):
    # --- Non-secret: file + env + default ---
    model_name: str = "qwen3-coder"
    executor_model: str | None = None      # falls back to model_name
    sandbox_mode: Literal["read-only", "workspace-write", "full"] = "workspace-write"
    parallel_tasks: int = Field(1, ge=1, le=10)
    log_level: Literal["DEBUG", "INFO", "WARNING", "ERROR"] = "INFO"
    max_cost_usd: float | None = None       # hard budget limit, None = unlimited

    # --- Secrets: env only, required ---
    api_key: str                            # BACKLOG_API_KEY
    api_base_url: AnyHttpUrl                # BACKLOG_API_BASE_URL

    model_config = SettingsConfigDict(
        env_prefix="BACKLOG_",
        env_file=None,
    )

def load_config(
    project_dir: Path | None = None,
    user_config: Path | None = None,
    cli_overrides: dict[str, Any] | None = None,
) -> CoreConfig:
    """Merge: cli_overrides > project .backlog.yml > user config.yml > defaults."""
```

Precedence (highest wins):
1. `cli_overrides` dict (populated by CLI flag parsing — not in this task)
2. `.backlog.yml` at `project_dir`
3. `~/.config/backlog/config.yml` (or `BACKLOG_CONFIG` env path)
4. Built-in defaults (above)

`api_key` and `api_base_url` are **not** loaded from files — they come only from
`BACKLOG_API_KEY` / `BACKLOG_API_BASE_URL` env vars. Attempting to read them
from a config file raises a validation error.

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | All secrets as env + valid defaults | `CoreConfig()` validates | `pytest -k config_valid` |
| AC2 | Missing `BACKLOG_API_KEY` | ValidationError (required secret) | `pytest -k secret_required` |
| AC3 | `api_key` present in `.backlog.yml` | ValidationError; key rejected from file | `pytest -k secret_from_file_rejected` |
| AC4 | Project file sets `sandbox_mode: read-only` | Merged config reflects project value | `pytest -k project_file_override` |
| AC5 | CLI override dict has `parallel_tasks=4` | Overrides project file value | `pytest -k cli_override_wins` |
| AC6 | User file sets `model_name: "custom"` | Applied when no project file present | `pytest -k user_file_fallback` |
| AC7 | `BACKLOG_CONFIG` points to custom path | Loaded in place of default user path | `pytest -k custom_user_path` |
| AC8 | `max_cost_usd=0` or negative | ValidationError (bound) | `pytest -k cost_bounds` |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Secrets from env only; non-secrets mergeable from files; type every field; validate bounds |
| Ask First | Adding a new secret field; changing the `BACKLOG_` env prefix; changing the file format |
| Never | Store a secret in a config file; load config from INI; use untyped `dict` for config |
