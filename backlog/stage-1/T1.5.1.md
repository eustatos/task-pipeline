# CI pipeline as the Stage 1 merge gate

## Objective
Set up a CI pipeline that runs the complete Stage 1 test suite and blocks any
merge to main when a contract-integrity test fails.

### Not Included
- Stage 2+ tests
- Deployment or release automation
- Benchmark gates (Stage 4)

## Context
DoD Level 0 is a gate: all C0.x criteria must pass in CI before any merge to main.
This pipeline is the enforcement mechanism for that gate.

## Tech Stack & Constraints
- Python 3.11
- CI runner: GitHub Actions or the project's equivalent
- Steps: install deps → `pytest tests/` → `mypy --strict src/`
- Branch protection requires this check before merge
- Runs on every pull request targeting main

## Input/Output Contracts

```yaml
# .github/workflows/stage1-gate.yml (shape only)
jobs:
  stage1-gate:
    steps:
      - run: pip install -r requirements-dev.txt
      - run: pytest tests/ -q          # full Stage 1 suite (see T1.0.0)
      - run: mypy --strict src/
```

> The workflow invokes the **suite** (`pytest tests/`) or a `make stage1` /
> `just stage1` target — not individual test file paths — so the gate does not
> rot when files are renamed.

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | PR with all tests green | Check passes, merge allowed | CI run on a sample PR |
| AC2 | PR with one failing test | Check fails, merge blocked | CI run on a red PR |
| AC3 | Branch protection | Merge requires the check | Repo settings review |
| AC4 | Every Stage 1 test file | Covered by the invoked suite | `pytest tests/ --collect-only` |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Run on every PR; block merge on failure; pin runner versions |
| Ask First | Making any check non-blocking; adding new required checks |
| Never | Allow merge on skipped checks; use `continue-on-error` on gate steps |

## Test Plan
