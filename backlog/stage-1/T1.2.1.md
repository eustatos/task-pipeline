# Define core State schema with a version field

## Objective
Define the base core State as a Pydantic model carrying a mandatory `version: int`
field. All persistent state in the pipeline derives from this base and is subject
to schema versioning.

### Not Included
- Migration converters (T1.2.2)
- Serialization and checksums (T1.2.4)
- Orchestrator/Executor state models (Stage 2)

## Context
DoD criterion C0.4 requires versioned, migratable state. A mandatory version field
is the anchor that makes forward/backward migration possible (ADR-004).

## Tech Stack & Constraints
- Python 3.11, Pydantic v2.x (see `backlog/_conventions.md`)
- The base model MUST reject construction without a version

## Input/Output Contracts

```python
class BaseState(BaseModel):
    version: int          # monotonic, starts at 1
    created_at: datetime  # tz-aware UTC
```

> `updated_at` is maintained by the store (T1.2.4), not stored in the base model,
> so non-temporal state (e.g. config snapshots) is not forced to carry it.

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | `version=1` | Model validates | `pytest -k base_state_valid` |
| AC2 | Missing `version` | ValidationError raised | `pytest -k version_required` |
| AC3 | `version=-1` | ValidationError raised | `pytest -k version_positive` |
| AC4 | Subclass adds fields | Subclass validates and keeps `version` | `pytest -k subclass` |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Keep `version` mandatory and positive; keep the base model immutable in shape |
| Ask First | Changing base field names; making `version` optional |
| Never | Default `version` silently; allow mutation of `version` without a migration |
