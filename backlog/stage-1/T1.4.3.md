# Config validation test matrix

## Objective
Write a parameterized test matrix covering missing required secrets, invalid
types, out-of-range values, defaults, file-merge precedence, and secret
isolation (env-only) for `CoreConfig`.

### Not Included
- The config model (T1.4.1) and startup wiring (T1.4.2)
- Secrets/vault validation
- Integration with deployment manifests

## Context
DoD criterion C0.6 requires validated configuration. This matrix is the evidence
artifact and runs in the Stage 1 merge gate (T1.5.1). It covers the 3-level merge
(CLI > project > user > defaults) and the secret-from-env-only rule introduced in
T1.4.1.

## Tech Stack & Constraints
- Python 3.11
- `pytest` + `pytest.mark.parametrize` + `monkeypatch` for env vars
- `tmp_path` for project/user config files
- Each case isolated: no env or file leakage between cases

## Input/Output Contracts

```python
CASES = [
    ("valid", {...}, None),                       # secrets in env, defaults applied
    ("missing_api_key", {...}, "BACKLOG_API_KEY"),  # required secret
    ("secret_in_project_file", {...}, "secret_rejected"),  # api_key in .backlog.yml
    ("bad_type", {...}, "int_parsing"),            # parallel_tasks: "abc"
    ("out_of_range", {...}, "greater_than_equal"),# parallel_tasks: 0
    ("project_over_user", {...}, None),            # project wins over user file
    ("cli_over_project", {...}, None),             # cli_overrides win
]
```

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | Valid env + defaults | Config validates | `pytest -k valid` |
| AC2 | Missing `BACKLOG_API_KEY` | Error names the env var | `pytest -k missing` |
| AC3 | `api_key` present in `.backlog.yml` | Rejected (secret env-only) | `pytest -k secret_rejected` |
| AC4 | Wrong type (non-int `parallel_tasks`) | Type error reported | `pytest -k type` |
| AC5 | Out-of-range `parallel_tasks=0` | Bound error reported | `pytest -k range` |
| AC6 | Project file vs user file conflict | Project value wins | `pytest -k precedence` |
| AC7 | CLI override vs project file | CLI value wins | `pytest -k precedence` |
| AC8 | Optional fields absent | Documented defaults applied | `pytest -k defaults` |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Isolate env and files per case; assert on the specific failing field |
| Ask First | Adding cases for experimental settings |
| Never | Depend on the developer's real environment; assert on message text verbatim |
