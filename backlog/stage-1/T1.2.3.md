# Migration test: v1 → v2 with 100% backward compatibility

## Objective
Write the migration test proving that every valid `StateV1` converts to a valid
`StateV2` without data loss, using a committed set of v1 fixtures.

### Not Included
- The migration framework itself (T1.2.2)
- Serialization/checksums (T1.2.4)
- Future migrations beyond v1 → v2

## Context
DoD criterion C0.4 requires 100% backward compatibility. This test is the evidence
artifact and runs in the Stage 1 merge gate (T1.5.1). Because migrations are typed
(T1.2.2), field preservation is asserted by field name, not by string matching.

## Tech Stack & Constraints
- Python 3.11
- `pytest` + `pytest.mark.parametrize`
- Fixtures stored under `tests/fixtures/state/v1/` (JSON)

## Input/Output Contracts

```python
@pytest.mark.parametrize("fixture_path", V1_FIXTURES)
def test_v1_to_v2(fixture_path: Path) -> None:
    # load StateV1 -> migrate to 2 -> validate StateV2 -> assert field-by-field
    ...
```

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | Each committed v1 fixture | Migrates and validates as `StateV2` | `pytest -k v1_fixtures` |
| AC2 | v1 fixture fields | All fields preserved (asserted by name) | `pytest -k no_field_loss` |
| AC3 | New v2-only field | Assigned its documented default | `pytest -k v2_defaults` |
| AC4 | Malformed v1 fixture | Rejected with `MigrationError` | `pytest -k malformed_v1` |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Assert field-by-field preservation; commit fixtures to the repo |
| Ask First | Changing a v1 fixture after merge |
| Never | Edit fixtures to match a broken converter; assert only on the version number |
