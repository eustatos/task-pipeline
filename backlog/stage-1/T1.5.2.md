# Add mypy --strict check for all tool modules

## Objective
Add a `mypy --strict` check over all Stage 1 modules and wire it into the CI gate,
failing the build on any type error.

### Not Included
- Runtime type validation (handled by Pydantic)
- Type checks for Stage 2+ modules
- Auto-fixing type errors

## Context
DoD criterion C0.1 requires 100% typed tools with 0 mypy errors. This task turns
that criterion into an automated gate rather than a manual review step.

## Tech Stack & Constraints
- Python 3.11
- `mypy` with `--strict`
- Config in `pyproject.toml` (`[tool.mypy]`) or `mypy.ini`
- No `# type: ignore` without an accompanying justification comment

## Input/Output Contracts

```toml
[tool.mypy]
python_version = "3.11"
strict = true
files = ["src"]
```

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | Clean `src/` | `mypy --strict` exits 0 | `mypy --strict src/` |
| AC2 | Untyped function added | Check fails with the location | `mypy --strict src/` |
| AC3 | `# type: ignore` without reason | Lint rule flags it | `pytest -k ignore_comment` |
| AC4 | CI wiring | Gate step runs the check | CI run log |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Run in CI; fail on any error; justify every suppression |
| Ask First | Excluding a module from the check |
| Never | Weaken `--strict` to pass; add blanket `ignore_errors = true` |

## Test Plan
- Type: `mypy --strict src/`
- CI: confirm the gate step executes and blocks on error.
- Self-verify: Run all 4 ACs. Cite command output and CI run.
