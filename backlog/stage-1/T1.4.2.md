# Fail-fast configuration validation at startup

## Objective
Validate configuration at process startup and abort with a clear, actionable
message listing every invalid or missing setting. No component starts on invalid
configuration.

### Not Included
- The config model itself (T1.4.1)
- Runtime reconfiguration or hot reload
- Secret validation against an external vault

## Context
DoD criterion C0.6 requires fail-fast with a clear error message (ADR-005).
Failing at startup prevents partially initialized processes with mixed defaults.

## Tech Stack & Constraints
- Python 3.11
- `CoreConfig` from T1.4.1
- Exit code non-zero on validation failure

## Input/Output Contracts

```python
def load_config_or_exit() -> CoreConfig:
    """Return validated config or print all errors and exit(1)."""
```

- The message lists every offending field and the expected env var name
- No partial config object is returned on failure

## Acceptance Criteria

| ID | Input | Expected Behavior | Verification |
|----|-------|-------------------|--------------|
| AC1 | Valid environment | `CoreConfig` returned | `pytest -k startup_ok` |
| AC2 | One invalid var | Non-zero exit; field named in output | `pytest -k startup_single_error` |
| AC3 | Two invalid vars | Both fields listed | `pytest -k startup_all_errors` |
| AC4 | Error message | Names the env var, not the Python field | `pytest -k startup_env_name` |

## Boundaries

| Tier | Rules |
|------|-------|
| Always | Report all errors together; exit non-zero; name the env var |
| Ask First | Changing the exit code; adding retry-on-invalid behavior |
| Never | Start with partial config; leak secret values into the error message |
